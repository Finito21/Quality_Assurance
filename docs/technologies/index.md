# Technologie

Technologie, z którymi tester spotyka się na co dzień. Nie trzeba być programistą, ale trzeba rozumieć, jak działa testowany system, żeby wiedzieć, gdzie szukać defektów i jak je opisać.

| Obszar | Strony | Po co testerowi |
|---|---|---|
| **Frontend** | [HTML](frontend/html.md), [CSS](frontend/css.md), [JavaScript](frontend/javascript.md) | czytanie struktury strony w DevTools, lokatory w automatyzacji, błędy w konsoli |
| **Backend** | [SQL](backend/sql.md) | sprawdzanie, czy dane zapisały się w bazie, przygotowanie danych testowych |
| **API** | [Podstawy API](api_testing/api_fundamentals.md), [HTTP](api_testing/http.md), [Uwierzytelnianie](api_testing/authentication.md), [Automatyzacja](api_testing/api_automation.md) | testowanie logiki bez interfejsu, szybsze i stabilniejsze niż testy przez UI |
| **DevOps** | [Docker](devops/docker.md), [Kubernetes](devops/kubernetes.md) | uruchamianie środowisk testowych, czytanie logów, diagnozowanie awarii |

!!! tip "Od czego zacząć"
    Jeśli dopiero zaczynasz, najpierw przeczytaj **HTML** i **HTTP**, potem **Podstawy API** i **SQL**. Docker i Kubernetes przydadzą się, gdy zaczniesz pracować w zespole z własnymi środowiskami.
